# Deep Dive (#2362) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A once-per-install (re-runnable) job that scans ~90 days of the principal's mail and calendar into a stored history summary, backfills contacts, drafts working rules / time-and-priorities / writing voice, and hands them to a Review session where the coordinator moves them to Google Docs and imports what the principal confirms; plus a pinned, two-document priorities record.

**Architecture:** System code (`src/onboarding/deep-dive/`) does the deterministic scan, backfill, drafting (direct `powerful`-tier router calls) and hand-off. No TypeScript talks to Google: the coordinator copies drafts to Docs and imports them using existing tools (MCP Docs, delegation to ceo-inbox/calendar, `executive-profile-update`, `doc-write`), guided by the lazy onboarding SKILL.md.

**Tech Stack:** TypeScript (ESM, Node 26), Vitest, Postgres (`working_docs`, config store), Nylas v3 via `CeoNylasClient` / `NylasCalendarClient`, Fastify routes, React console.

**Spec:** `docs/wip/2026-11-23-deep-dive-design.md`

## Review Focus

1. **Mailbox with very little history** (new account, 3 messages): the scan completes, the summary says so, drafts say there was too little to go on — no crash, no empty-document hand-off without explanation. → Task 3 test `summarises a near-empty mailbox`.
2. **Principal address appears as correspondent** (self-sent, CC to self, alias mailboxes): never counted as a correspondent, never backfilled as a contact. → Task 3 test `excludes the principal's own addresses`, Task 5 test.
3. **Process restart mid-scan or mid-draft**: resumes from the last completed stage without re-scanning or creating a second review task. → Task 4 test `resumes drafting without rescanning`.
4. **Re-run while a run is in progress**: refused with a clear message, not a second concurrent job. → Task 9 test `refuses a re-run while running`.
5. **Nylas 429 storm**: pace slows, run continues; caps end it as truncated rather than failing. → Task 2 test `doubles the page delay after a 429`.

- Heuristics (pin in README and tests): `kind` from `classifyEmailSender`; `twoWay` = received ≥1 and sent ≥1 and total ≥ `TWO_WAY_MIN_MESSAGES`; reply latency = received→next principal-sent message in the same `threadId`; unopened = `unread` and older than 7 days, grouped by sender domain; handed-off = principal-sent messages whose subject starts `Fwd:`/`FW:` to a non-principal; recurring = events sharing `masterEventId` (or `recurrence` on the master) with ≥3 occurrences in the window; kept-clear blocks = weekday time ranges with no events in ≥75% of weeks during 08:00–18:00 principal-local, ≥60 min; declined/moved = principal participant status `no` or `originalStartTime` ≠ `startTime`; `timeSpent` organisation key = domain; voice sample = up to `VOICE_SAMPLE_SIZE` sent messages, distinct recipients first, bodies HTML-stripped.

Hitting a cap sets `coverage.truncated` and stops.
